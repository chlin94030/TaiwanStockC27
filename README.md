# Alpha Radar PRO Global V27

台股短、中、長線決策台。V27加入十面向分散模型、台美日韓情境、0050可選配置，以及電腦／手機自適應介面。iPhone部署請使用同層檔案包並閱讀 `MOBILE_UPLOAD.txt`。

**先讀 `START_HERE.txt`。程式包不含真實行情庫，也不自動下單。** 互動HTML預覽使用合成資料；實際選股須載入正式資料。

| 頁籤 | 日常用途 |
|---|---|
| 選股總覽 | 篩選週期與族群；同股合併；看買區、防守價、2R及依據 |
| 盤中雷達 | 掃描模型候選池50／100／150檔；核對成交時間、買區及價量；30／60／120秒更新 |
| 明日布局 | 檢查資料日期，整理下交易日候選、限價及出場檢查 |
| 個股診斷 | 輸入代號或公司名；看三模型判斷、交易計畫及可切換K線／籌碼 |
| 資金配置 | 設本金與配比；分開看目標持倉／本週一批；合併同股並計算股數、費用及風險 |
| 資料與策略 | 載入資料包、績效摘要、分點CSV；更新本機資料；看模型與來源日期 |

## 沿用現有資料及安裝

### 已有CLAUDE資料：優先採這條路

1. 保留原程式及資料備份。解壓本包，將**裡面的檔案與資料夾**放入原專案根目錄，讓 `app.py` 在根目錄；不要把整個ZIP當成程式上傳。
2. 保留原 `data/`、`artifacts/`、既有憑證及GitHub的 `kosto-data`、`kosto-research` Releases。更新程式不需要刪除這些資料。
3. 本機直接沿用 `artifacts/bundle.npz`，也可在啟動畫面匯入CLAUDE的 `bundle.npz`。
4. 雲端繼續使用原儲存庫，Streamlit入口為 `app.py`。沿用原 `GITHUB_REPO`；公開儲存庫讀資料通常不需token，私人儲存庫依現有權限設定。
5. `.github/workflows/pipeline.yml` 已加入安全JSON摘要的發布。若網頁上傳漏掉隱藏資料夾，可用 `pipeline_workflow_COPY.txt` 建立同名路徑；主題設定參考 `streamlit_config_COPY.txt`。
6. 更新後執行一次既有每日流程。尚未產生新JSON時，介面仍可讀舊 `report.zip` 的JSON摘要，不載入遠端 `results.pkl`。

GitHub排程設定為台北時間平日23:10；實際啟動、完成與可用性以Actions狀態為準。第一次完整建立行情可能需要多輪下載。只有NPZ時請沿用每日流程，NPZ不能還原完整原始歷史。

### 原Alpha V25行情也能沿用

把原 `data/v21_universe_lab/` 放在專案同一路徑，或在啟動畫面匯入原 `V21_DATABASE.zip`，選「沿用V25行情」。程式唯讀轉入價量，另建快取，不更動來源SQLite；備份會核對路徑、大小及可用的雜湊。

這條路預設**價格確認**模型。原庫未含的營收、財報、法人與集保會明示不足，不能據此宣稱已有完整成長模型。完整融合優先使用CLAUDE完整資料及更新來源。

### 本機啟動

建議Python 3.12。Windows雙擊 `start_windows.bat`；Mac使用 `start_mac.command`。第一次安裝套件需要網路。也可在專案根目錄執行：

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Mac/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

啟動後匯入正式資料，或按「開啟操作示範」。示範資料不會顯示真實可買訊號。`ALPHA_DESK_BUNDLE` 可指定本機NPZ路徑；`ALPHA_DESK_DEMO=1` 僅供展示。

## 每天怎麼用

**盤後決定明日標的：** 確認頁首資料到最近交易日，再開「明日布局」，預設中／長線。選週期、下載清單，到「資金配置」看本週一批預算。今天未更新完成，不能把舊清單當成本日盤後結果。

**盤中找標的：** 開「盤中雷達」，選週期與掃描上限，預設60秒更新。模型合格、資料夠新、有效當日成交在買區，且非漲跌停、價差未過大時，才顯示「可分批布局」。這是候選池掃描，並非全市場逐筆掃描；基本模型仍截至最近收盤。

**查個股：** 在「個股診斷」輸入代號或公司名。先看所選週期的判斷與原因，再看買區／追價上限／防守價。資料包外、母池外、條件未過分別說明，不編造分數。左側持股代號只用於續抱；自選觀察不視為已持有。

**進場範例：** 買區內分3筆，第一筆先做本批金額1/3，其餘待條件持續符合再評估；不是見到名單就一次買滿。超過追價上限等拉回，低於買區等止跌。非一般盤中時段、收盤競價、舊成交或缺報價不顯示可立即買入。未成交資金保留。

**出場檢查：** 跌破防守價檢視減碼與原理由；2R可評估減1/3，3R列於清單；跌出續抱門檻，在固定檢查日檢視換股。R是買區中點至防守距離。價位是操作參考，尚未納入原回測，也不保證能以該價成交。

## 模型與資金安排

| 週期 | 預設配方 | 檢查與批次 | 持有續抱門檻 |
|---|---|---|---|
| 短線5交易日 | v1.5慢變成長動能＋50%價格Alpha假說，用中線標籤估計 | 每5交易日檢查，1批 | 前25名 |
| 中線20交易日 | 精簡成長模型＋50%相對強度假說 | 分4批，每週檢查一批 | 前20名 |
| 長線60交易日 | 精簡模型／趨勢錨＋50%領先股假說，名次加權 | 分12批，每週檢查一批 | 前25名 |

長線沿用來源60交易日定義。不是每週重買全部12批，也不是每月僅買1/3。V27以來源模型80%＋十面向先驗20%建立候選，並可在介面切回來源定稿模型；詳細配方見 `V27_MODEL_CARD.md`。

配比是可調整範例，未替使用者判定風險承受度：

| 配置範例 | 現金 | 0050核心 | 短線 | 中線 | 長線 |
|---|---:|---:|---:|---:|---:|
| 核心優先 | 20% | 60% | 0% | 10% | 10% |
| 均衡配置（預設） | 10% | 40% | 0% | 30% | 20% |
| 主動操作 | 10% | 20% | 30% | 0% | 40% |

短、中線常重疊，範例擇一配置。自訂配比須合計100%。單股預設10%、同族群直接個股25%、每檔至防守價的風險預算0.5%總本金；跨模型同股先合併再套上限，未用資金回到現金。

「目標持倉」看整體目標；「本週新一批」中線只投入目標1/4、長線1/12。0050顯示核心預算，未計ETF股數及費用，已持有者不重複買入。此頁是本金試算，未輸入既有股數，**不會自動扣除現有部位或算實際補買差額**。族群上限未穿透0050成分股；費用緩衝未計券商最低費用。

## K線與籌碼

日／週／月K可切換；日K的5／20／60／120／240均線對應週／月／季／半年／年線，另有10日線。週、月K上均線單位同步改為週、月，歷史不足會說明。可選布林、成交量、KD、MACD、法人、資券、大戶及分點。

外資、投信、自營商各列最新日、近5／20日及連續買賣超，完整資料才評論同步進出；缺值不補0。資券顯示實際觀測日。大戶是集保≥400張週資料，不等同盤中主力進出。

主力分點在「資料與策略」匯入有來源CSV：`date,ticker,buy_lots,sell_lots,net_lots,source`，單位張、淨額須等於買減賣；沒有就顯示未接入。舊包缺少原始週基準日或新欄位，介面會明示限制。

## 更新與驗證

有本機原始行情可按「補上最近交易日的正式價量與籌碼」；只補最近交易日，不是補全歷史。上市／上櫃行情未同步齊全時保留前次快取。只有NPZ時沿用GitHub每日流程。更新完成再按「重新載入最新資料」。最近日補齊不取代營收／財報全套更新。

研究CLI保留 `python cli.py bundle`、`python cli.py research --quick`，完整用途見 `python cli.py --help`。`docs/`中的協議與技術說明屬來源歷史，不能當作V27新操作層已重跑的績效證明。

```bash
python -m pip install pytest==9.1.1
python -m pytest -q
python cli.py validate-v27 --bundle artifacts/bundle.npz
# 可選：重建離線合成預覽，第一次會建立示範資料
python scripts/export_interface_preview.py artifacts/interface_preview.html
```

本版驗證程式與流程，未以使用者完整真實行情重新證明最優報酬。正式資料流程會輸出 `artifacts/v27_validation.json`，依固定三窗口與回撤門檻比較來源模型。MIS與海外行情仍須在使用者環境及交易時段確認；失敗時維持等待或中性。詳見 `V27_QA_REPORT.txt`。
